# 주차장 여석 판별 2D 맵 (컴퓨터비전 3조)

삼각대로 고정해 찍은 교내 주차장 영상에서 차를 검출합니다. 차가 바닥에 닿는 점(**지면 접점**)을 Homography로
**위에서 본 2D 지도**에 옮긴 뒤, 칸마다 비었는지 판정합니다. 결과는 원본 영상과 지도를 나란히 보여주는 영상과
칸 상태 CSV로 나옵니다.

- **제안 방식**: 바닥(주차선)은 Homography로 펴고, 높이가 있는 차는 바닥에 닿는 부분(지면 접점, 차 바닥 영역)만 지도로 옮겨 지도 위에서 판정합니다.
- **비교 기준**: 논문 ② 방식. 영상 위 칸 폴리곤 안에 박스 중심점이 들어가면 점유로 봅니다.
- 설계 기준과 결정 이유는 [CLAUDE.md](CLAUDE.md)에 있습니다.
- **새 영상을 추가하는 팀원은 [docs/TEAM_GUIDE.md](docs/TEAM_GUIDE.md)를 따라 하세요** (촬영 → 등록 → 점 찍기 → 확인 → 라벨링 → 평가).

1차·2차·3차는 쌓아 가는 설계 단계입니다. **기본 설정(최종 시스템)은 세 단계가 모두 적용된 상태**입니다.

| 단계 | 더해지는 것 | 상태 |
|---|---|---|
| 1차 | 지면 접점 → 2D 지도에서 칸 점유 판별 (빈칸 초록 / 점유 빨강 / 판단불가 회색) | 완료, 평가 완료 |
| 2차 | 차 바닥 영역 + 칸별 겹침 비율: 선 밟은 차의 옆 칸도 점유, 많이 걸치면 침범(노랑) | 적용, 침범 표시는 성능 한계 있음 |
| 3차 | ByteTrack 추적 + 통로 정지 시간 → 불법주차(주황) | 적용, 평가용 영상 필요 |

## 1. 설치

Ubuntu, Python 3.10 이상, NVIDIA GPU 권장 (RTX 4060에서 확인).

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
pytest -q          # 합성 데이터 단위 테스트 59개
```

- 검출 모델(`yolo26x-seg.pt`, COCO 사전학습)은 처음 실행할 때 `models/`에 자동으로 받아집니다. 학습 데이터는 필요 없습니다.
- 데이터(`data/`), 영상, 모델 가중치, 결과(`outputs/`)는 저장소에 넣지 않습니다. 영상은 공유 드라이브에서 받습니다.
- 설정값(모델, 해상도, 임계값, 칸·차 크기)은 모두 [configs/default.yaml](configs/default.yaml)에 있습니다.

## 2. 용어와 폴더 구조

| 용어 | 뜻 |
|---|---|
| lot | 주차장. 주차장마다 지도(`map.json`)가 1개입니다. |
| cam | 삼각대 한 위치. 위치마다 Homography `H`가 1개입니다. |
| clip | 영상 파일 1개. 같은 cam의 clip은 같은 H를 씁니다. |

```
data/
  lots/<lot>/map.json, map_bev.png             # 칸·통로 좌표 (m), 탑뷰 배경
  cams/<lot>_<cam>/H.json, ref_frame.png        # 대응점, H, 재투영 오차
  clips/<clip_id>/video.mp4, meta.json          # meta: lot, cam, condition, valid_sec, split
  clips/<clip_id>/gt_frames/, gt_occupancy.csv  # 라벨링용 프레임, 정답
outputs/<clip_id>/
  detections.jsonl                              # 검출 캐시 (한 번만 돌림)
  occupancy.csv, split_view.mp4, events.csv     # 칸 상태, 결과 영상, 불법주차 이벤트
```

`meta.json` 예:
```json
{"lot": "lotA", "cam": "lotA_cam3", "condition": "mid", "valid_sec": [24.0, 853.0], "split": "tune"}
```
`valid_sec`는 카메라가 고정된 구간입니다(촬영 시작·끝의 흔들림 제외). `split`은 `tune`(임계값 조정용) 또는 `test`(최종 보고용)입니다.

## 3. 실행 방법

GUI 도구(setup_cam, build_map, label_gt)는 OpenCV 창으로 열리고, 화면에 키 조작법이 나옵니다.
공통 키는 `u` 되돌리기, `s` 저장, `q` 종료입니다.

### 3.1 새 카메라 위치 설정 (cam마다 1회)
```bash
python tools/setup_cam.py --clip data/clips/lotA_cam3_mid
```
1. 선이 잘 보이는 주차칸 모서리를 클릭하고, 터미널에 그 점의 지도 좌표(m) `x y`를 입력합니다. **6개 이상**, 화면 양 끝과 여러 줄에 넓게 찍습니다.
   - 점이 4개 이상 모이면 화면 위쪽에 커서 위치의 지도 좌표가 나옵니다. 다음 점의 좌표를 찾을 때 참고하면 됩니다.
   - 같은 주차장의 두 번째 cam부터는 **첫 cam과 같은 좌표 기준**으로 입력해야 합니다.
2. `v`로 검증점 2~4개를 찍습니다. H 계산에 쓰지 않고 오차 확인에만 씁니다.
3. `s`로 저장합니다. 그 주차장의 첫 cam이면 지도 뼈대와 탑뷰 배경도 함께 만들어집니다.

### 3.2 지도에 칸 그리기 (주차장마다 1회)
```bash
python tools/build_map.py --lot lotA --cam lotA_cam3
```
- `1` 줄 모드: 첫 칸 앞 모서리 → 줄 끝 → 첫 칸 뒤 모서리를 클릭한 뒤, 칸 수와 이름(예: `10 A`)을 입력합니다.
- `2` 다각형 모드: 불규칙한 칸, 통로, 금지구역을 직접 클릭합니다.
- 칸은 **주차선 중심선** 기준으로 그립니다. 이웃 칸 사이에 틈이 없어야 합니다.
- 두 번째 창에 원본 영상 위에 지도를 되돌려 그린 그림이 나옵니다. 실제 선과 맞는지 확인하세요.

### 3.3 영상 처리 (clip마다)
```bash
python -m parking.pipeline --clip data/clips/lotA_cam3_mid             # 칸 상태 CSV + 결과 영상
python -m parking.pipeline --clip data/clips/lotA_cam3_mid --no-video  # CSV만 (빠름)
```
- 처음 실행하면 YOLO 검출을 돌려 `detections.jsonl`에 저장합니다. 이후에는 이 캐시를 읽어 판정만 다시 합니다.
- 결과 영상 `split_view.mp4`의 왼쪽은 원본 영상에 칸 상태와 검출 결과를 겹친 것이고, 오른쪽은 탑뷰 지도에 칸 상태, 접점, 통로를 그린 것입니다.

### 3.4 정답 라벨링
```bash
python tools/sample_frames.py --clip data/clips/lotA_cam3_mid --every-sec 10
python tools/label_gt.py --clip data/clips/lotA_cam3_mid
```
- 칸 안쪽 바닥을 클릭할 때마다 상태가 바뀝니다: 0 빈칸 → 1 점유 → 2 침범(선에 걸친 차) → -1 판단불가 → 0
- **클릭한 변경은 뒤 프레임에도 이어서 적용됩니다.** 차가 떠난 프레임에서 다시 클릭해 되돌려야 합니다.
- 시스템 예측은 화면에 보이지 않습니다. 테스트용 clip은 결과 영상을 보기 전에 라벨링해야 공정합니다.
- 특정 구간만 촘촘히 뽑으려면: `--every-sec 2 --start 455 --end 705 --max 200`

### 3.5 평가
```bash
python eval/evaluate.py --clips data/clips/lotA_* --split test    # 지표 상세 (줄·조건별)
python eval/compare.py  --clips data/clips/lotA_* --split test    # 방식 비교 표 -> outputs/compare_test.md
python eval/evaluate.py --clips data/clips/lotA_* --events        # 3차 불법주차 이벤트
```
3차 정답은 `data/clips/<clip>/gt_events.csv`에 직접 적습니다:
```
event_id,clip_id,type,zone_id,start_sec,end_sec
E01,lotA_cam4_staged,aisle_parking,AISLE1,42.0,135.5
E02,lotA_cam4_staged,pass_through,AISLE1,150.0,158.0
```

### 4.2 칸 점유 판별 (핵심)

"최종"은 기본 설정(1차+2차+3차)입니다. 3차는 점유 판정에 영향을 주지 않습니다.

**테스트 clip (cam1 + cam2, 79프레임, 칸 판정 2,958건)**

| 방식 | 빈칸 Precision | 점유 Recall | Accuracy | 빈자리 수 MAE | 점유→빈칸 (치명적) | 빈칸→점유 |
|---|---|---|---|---|---|---|
| **최종** (지면 접점 + 차 바닥 영역 겹침) | **1.000** | **1.000** | 0.999 | 0.04 | **0** | 3 |
| 1차만 (지면 접점 + 깊이 오프셋 0.9m) | 1.000 | 1.000 | 1.000 | 0.00 | 0 | 0 |
| 1차만, 깊이 오프셋 없음 (원래 설계) | 0.927 | 0.942 | 0.935 | 0.01 | 95 | 96 |
| 논문 ② (박스 중심) | 0.846 | 0.870 | 0.885 | 1.13 | 215 | 126 |

**튜닝 clip (cam3, 208프레임, 칸 판정 9,568건, 그중 149프레임이 침범 연출 구간)**

| 방식 | 빈칸 Precision | 점유 Recall | Accuracy | 빈자리 수 MAE | 점유→빈칸 (치명적) |
|---|---|---|---|---|---|
| **최종** | **0.992** | **0.990** | **0.995** | **0.22** | **44** |
| 1차만 | 0.945 | 0.930 | 0.968 | 1.46 | 304 |
| 1차만, 깊이 오프셋 없음 | 0.943 | 0.927 | 0.967 | 1.50 | 314 |
| 논문 ② (박스 중심) | 0.818 | 0.730 | 0.878 | 5.62 | 1,168 |

- "점유→빈칸"은 **차가 있는 칸을 빈칸으로 안내한 횟수**입니다. 사용자에게 가장 치명적인 실수입니다.
  - 논문 ② 대비: 테스트 215건 → 0건, 튜닝 1,168건 → 44건
- **1차 (지면 접점)의 효과**: 박스 중심은 차 높이만큼 카메라 반대쪽(뒤 칸)으로 밀려 찍히고, 지면 접점은 그렇지 않습니다.
  합성 실험(`tests/test_contact.py`, `tools/debug_synthetic.py`)에서 예측한 차이가 실제 영상에서도 확인됐습니다.
- **깊이 오프셋 0.9m**: 지면 접점은 차 바닥의 카메라 쪽 끝이라, 비스듬히 보이는 먼 칸에서는 옆 칸으로 넘어갑니다.
  접점을 차 폭의 절반만큼 카메라 반대쪽으로 밀어 해결했습니다(테스트 치명적 실수 95 → 0).
- **2차 (차 바닥 영역)의 효과**: 1차는 차 한 대당 칸 하나만 표시해서, 선 밟은 차가 걸친 옆 칸은 빈칸으로 남았습니다.
  2차는 차 바닥 사각형이 15% 이상 겹친 칸을 모두 점유로 봅니다(튜닝 치명적 실수 304 → 44).
  - 대가: 바르게 선 차가 옆 칸에 15% 걸친 것으로 계산되면 빈칸을 점유로 봅니다(테스트 3건).
  - 통로를 가로지르는 차는 사각형을 가로로 눕힙니다. 접점이 통로에 있고 보이는 바닥 경계가 칸과 수직으로 3m 이상 길 때입니다.
    눕히지 않으면 세로 사각형이 앞 칸으로 뻗어 빈칸을 점유로 봅니다(튜닝 빈칸→점유 31 → 4).
  - 튜닝의 개선 중 일부(C11·C12)는, 앞차에 가려 검출되지 않는 차 옆의 사각형이 두 칸을 덮어서 우연히 맞은 것입니다.
- 남은 오류: 앞차에 가려 검출되지 않는 차, 연출 구간에서 움직이는 차
- 처리 속도:
  - 검출: 약 0.33초/프레임 (RTX 4060, 영상 디코딩 포함)
  - 판정, 추적, 결과 영상 생성: 약 0.08초/프레임
  - 논문 ③은 장당 약 1.5초

### 4.3 2차: 칸 침범 판별
- 방법: 마스크 아래 경계를 지도에 옮기고, 카메라 쪽 끝을 기준으로 표준 차 크기(1.8×4.7m) 사각형을 칸 방향에 맞춰 놓습니다.
  - 겹침 비율은 **차 면적 기준**으로 계산합니다. 칸이 차보다 커서 칸 면적 기준이면 꽉 찬 차도 70%밖에 안 됩니다.
  - 15% 이상 겹친 칸은 모두 점유(빨강)입니다. 가장 많이 겹친 칸 말고도 30%(`tau_straddle`) 이상 겹친 칸이 있으면 두 칸 모두 침범(노랑)입니다.
- 결과(침범 장면 단위: 정답 침범 칸과 예측 침범 칸이 하나라도 겹치면 맞음):

| clip | 침범 기준 | 맞음 | 놓침 | 오경보 장면 |
|---|---|---|---|---|
| cam3 연출 구간 (tune, 침범 장면 75장) | 0.15 (논문 ③) | 36 | 39 | 172 |
| cam3 연출 구간 (tune) | **0.30 (채택)** | 22 | 53 | **0** |
| cam1·cam2 (test, 침범 없음, 79장) | 0.30 | – | – | 11 |

- **한계**:
  - 차 바닥 사각형의 좌우 위치 오차(±0.3~0.5m)가 칸 안 여유(0.34m)와 비슷합니다. 그래서 살짝 걸친 차와 바르게 선 차를 구분하기 어렵습니다.
  - 연출한 차는 대부분 칸과 비스듬히 서 있는데, 사각형은 칸 방향으로 가정합니다. 보이는 경계로 차 방향을 추정해 보았지만 개선되지 않았습니다.
- 침범 기준 0.30은 cam3에서 골랐습니다. 최종 성능을 보고하려면 다른 위치나 다른 날의 연출 영상이 필요합니다.

### 4.4 3차: 불법주차 탐지
- 방법:
  - 검출 캐시(2fps)에 ByteTrack을 붙여 차마다 지도 위 궤적을 만듭니다.
  - 통로 안에서 5초 평균 속도가 0.3m/s 미만인 상태가 60초 이상 이어지면 이벤트입니다.
  - 통로는 마주 보는 칸 줄 사이에 자동 생성합니다(AISLE1 = A~B줄, AISLE2 = C~D줄).
- 결과:
  - 현재 세 clip에는 통로 장기 정차가 없어 이벤트 0건, 오경보 0건입니다.
  - 기준을 10초로 낮추면 cam3 9분 42초~10분 17초 AISLE2의 35초 정차 1건이 잡힙니다. 추적과 정지 판정은 동작합니다.
- **평가 대기**: 통로 1분 이상 정차, 통과, 잠깐 멈춤 장면을 연출해 찍고 `gt_events.csv`를 만들어야 합니다.

### 4.5 결과를 볼 때 주의할 점
- 데이터가 **주차장 1곳, 테스트 clip 2개**뿐입니다. 테스트 정확도 1.000은 "이 두 영상에서 모두 맞았다"는 뜻입니다.
- 깊이 오프셋 0.9m는 튜닝 clip에서도 약간 나았지만(치명적 실수 314 → 304), **채택 결정은 테스트 결과를 본 뒤에 했습니다.**
  새 테스트 영상으로 다시 확인하는 것이 좋습니다.
- 화면 밖이나 크게 가려진 칸은 판단불가로 빼고 정확도에서 제외했습니다. 테스트 clip의 커버리지는 약 81%(46칸 중 판정 가능한 칸 비율)입니다.
